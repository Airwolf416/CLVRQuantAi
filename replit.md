# CLVRQuantAI

## Overview
CLVRQuantAI is a luxury, mobile-first market intelligence dashboard for real-time analysis across crypto, equities, commodities, and forex. It provides AI-driven market insights, a macro calendar, personalized alerts, and a morning brief to support informed trading decisions. The project aims to transition from AI-originated signals to a deterministic quant scorer, with AI serving a veto-only role, enhancing signal reliability and precision.

## Recent Decisions
- **Scanner "no signal" root cause — volume was read from the forming bar + one crypto-calibrated range floor (Jul 2026):** `computeQuantIndicators` read `volumeRatio` from the CURRENT forming hourly bar (`volumes[n-1]`), whose volume is 0/partial until the hour closes — so `volumeRatio ≈ 0` on virtually every scan. That silently (a) made a volume `volSurge` impossible (the old `(vr||1)>=2` could never fire, killing the anti-chase breakout exception) and (b) collapsed the no-momentum gate to "range only", and its single 1.5% floor is **crypto-calibrated** so it silenced calmer markets (a big S&P name moves ~0.5%/day, FX far less). Fixes, all in `/api/quant`: (1) `volumeRatio` uses the last **CLOSED** bar over ≤20 closed bars; when the feed carries no volume at all (**Yahoo reports 0 volume on EVERY FX/commodity bar**) it is `null` = "unknown", never 0 — gates treat null as range-only and never as a surge or as "low volume". (2) Per-asset-class no-momentum range floor `NO_MOMENTUM_RANGE_PCT = {crypto:1.5, equity:0.8, commodity:0.8, fx:0.3}` (user-approved), normalized for plural class strings. (3) `neutral_source` is now stamped on every NEUTRAL path (`no_momentum`/`anti_chase`/`regime_block`/`cooldown`/`macro_halt`/`news_conflict`/`llm_direct`) for attribution. (4) **Single NEUTRAL-normalization chokepoint**: any non-directional-and-not-SUPPRESSED result has entry/SL/TP1-3/rr nulled, `win_probability=0`, `conviction_tier="D"` — so a NEUTRAL can never again ship the LLM's long-shaped reference levels + an 82% number. SUPPRESSED contract unchanged (rr-null only). Sits ABOVE the `ai_signal_log` persist, so NEUTRAL is never written; fails open per-card.
- **NEUTRAL is never a trade card (Jul 2026 — the REAL root cause of "SHORT card with long levels"):** `/api/quant` can return `signal=NEUTRAL` WITH reference entry/SL/TP levels; the geometry guard rightly skips it (no direction) and it's never persisted — so every server surface looked clean while the scanner still showed bad cards. The leak was client-side: `SignalCard` derived its badge via `signal.includes("LONG") ? LONG : SHORT`, so NEUTRAL rendered as "↓ SHORT" over long-shaped levels. Convention now: **direction comes ONLY from an explicit LONG/SHORT in the signal string — a binary long/short fallback is forbidden anywhere in the UI.** `SignalCard` renders nothing for non-directional results; `QuantScanner` gates buckets on `dirOf()` and shows NEUTRAL rows in their own "NO DIRECTIONAL EDGE" section (+ ScanSummary count); `/api/quant` forces `rr=null` for non-directional results (including LLM-supplied `tp1.rr_ratio`) and the absolute-math rr fallback is directional-only. Also: `/api/signal-history` (Account page, paid view) now runs the same silent read-time geometry repair as `/api/signals/feed`.
- **Shared geometry guard at ALL card emission points (Jul 2026):** `server/lib/geometryGuard.ts` `enforceGeometry()` is the LAST gate before any trade card leaves the server — wired in `/api/quant` (also covers scanner Execute + transparency cards), `/api/ai/analyze`, `/api/kronos`, `promptV2Runner`, `dailyBrief`, the auto-scanner emission (before `liveSignals`/`saveSignalRecord`/`logSignal`), and `/api/ai/log-trades`. **Guard runs BEFORE persistence, not just before `res.json`** — in `/api/quant` it sits above the `ai_signal_log` persist block so the stored row (feeds `/api/signals/feed`, outcome resolver, stats) carries the SAME repaired levels as the response; persist-before-guard was how SHORT cards with long-side levels leaked into the feed despite a "working" guard. `/api/signals/feed` additionally repairs rows at READ time (display-only, `silent:true` so historical bad rows don't spam telemetry every poll) to cover legacy rows stored pre-fix. The absolute-math rr fallback in `/api/quant` is skipped when `geometry_auto_corrected` is set (guard's null rr is intentional for unmirrorable legs). Per-leg wrong-side mirror (2×entry−level), `-UNMIRRORABLE` suffix keeps originals, DIRECTIONAL R:R (null when stop distance ≤ 0 — never absolute math), `geometry_auto_corrected` flag drives the client "LEVELS AUTO-ALIGNED" chip. Repair-only (never flips badge), fails open per-card. **Convention: the client NEVER recomputes R:R from prices** — `SignalCard` trusts server `rr` (finite or "—"). Older mirrors (signalHardening Gate 0, pre-LLM inline fix, archetype flip, edgePolicy) stay as-is; the shared guard is idempotent so double-guarding is harmless.
- **Directional-geometry repair + compliance relabel (Jul 2026, live):** the shared gate `applySignalHardening` (`server/lib/signalHardening.ts`) opens with Gate 0 — any wrong-side SL/TP is mirrored across entry (1R stop / 1.5R / 2.5R) with a TP-ladder monotonic guard, and ALL downstream gates + returns use the repaired levels. All three callers propagate repaired levels (`promptV2Runner.ts` also writes them back into `plan.targets[0/1]` + `tp1/tp2` aliases). `DIRECTION_GEOMETRY_MISMATCH` rejection reason exists for reject mode. Customer-facing win-rate/performance claims relabeled (e.g. daily brief "model confidence" → "setup quality"); owner-only (`isOwner`-gated) diagnostics untouched; Track Record tab, personal Journal, and Kelly examples deferred to counsel.
- **336-bar 1h lookback (14d × 24h)** is the canonical archetype-classifier window everywhere — `/api/quant`, `/api/ai/analyze`, `/api/kronos`. Anything shorter silently collapses the daily-ATR aggregate.
- **Hourly cron + materialized views** (`archetype_stats`, `archetype_scorecard`) feed all per-archetype stats; the TS-direct fallback in `getArchetypeStats` only fires when the MV is empty or unreachable (cycle-safe).

## System Architecture
The application features an Express (TypeScript) backend and a React (JSX) frontend, served via Vite on a single port. Data is persisted in PostgreSQL using Drizzle ORM. A Python FastAPI quant microservice handles deterministic quantitative scoring. The UI/UX employs a navy and gold theme with Playfair Display and IBM Plex Mono fonts.

**Key Architectural Components & Features:**
- **Quant Microservice:** A Python FastAPI service (`quant/`) generates deterministic quantitative scores, including modules for scoring, risk management (stop-loss, sizing), regime detection, GARCH modeling, and microstructure analysis.
- **Node-Python Bridge:** `server/quantClient.ts` facilitates communication between the Node.js backend and the Python quant microservice.
- **Real-time Data Aggregation:** Aggregates 1-minute OHLCV bars from sources like Hyperliquid, Binance, and Yahoo Finance.
- **Signal Generation & Hardening:** Signals originate from the quant service, are subject to cost/EV gates, and an AI veto. Signal hardening rules (e.g., `MIN_RR_AFTER_FRICTION`) optimize throughput and reduce noise.
- **Statistical Brain:** An empirical edge engine (`server/lib/statisticalBrain.ts`) analyzes historical trade data to compute win rates, expected returns, and resolution times per (token, direction) combo. It derives strict limits for Take Profits, Stop Losses, and Kill Clocks, issuing verdicts: **INVERT** (WR<15% & n≥20, opposite side not also weak — flip direction), SUPPRESS (WR<25% & n≥20), CAUTION, NORMAL, or PREFERRED. This brain context is integrated into the AI's prompts and can veto/flip signals.
- **Edge Policy (Phase 0 — INVERT loser combos):** `applyEdgePolicy(token, direction, rawConvictionPct)` and `recalibrateConviction()` in `server/lib/statisticalBrain.ts` translate brain verdicts into deterministic post-LLM actions: SUPPRESS drops the card; INVERT mirrors stop/targets around entry via `mirrorPrice()` and flips direction; conviction recalibration clamps INVERT/SUPPRESS verdicts at ≤25 and caps any raw≥50 at 40 for NORMAL/CAUTION, while PREFERRED passes through untouched. Wired into BOTH `/api/ai/analyze` `hardenTradeIdeas` and `/api/kronos` BEFORE `hardenSignal()`. Cards expose `edgePolicy` + an `edge-inverted` hardener flag; INVERT forces `materiallyMutated=true` to trigger rationale regen. Falls open on any error.
- **Chart Vision:** `server/lib/chartRenderer.ts` generates SVG candlestick charts with technical overlays (EMAs, S/R, entry zones), converts them to PNG, and sends them as multimodal input to Claude for visual analysis validation.
- **Enhanced AI Analysis (`/api/ai/analyze`):** Integrates the Statistical Brain, Chart Vision, and intraday Execution Levels (VWAP, ORH, ORL) into the AI's context for a comprehensive analysis of user-specified tickers.
- **Daily Brief Integration:** The Statistical Brain context is used to bias trade idea selection in the daily email brief and Telegram posts, favoring empirically winning setups and avoiding suppressed ones.
- **Trade Idea Asset Class Selector:** UI allows filtering trade ideas by asset class (All, Crypto, Equities, Commodities, Forex), dynamically adjusting market types (PERP/SPOT) and filtering signals accordingly.
- **Telegram Autoposter:** A unified helper (`server/lib/buildEnrichedReasoning.ts`) creates consistent, branded captions for live signals and daily brief trade ideas, posted via a dedicated webhook. Includes admin tools for testing posts.
- **Email & Update Management:** Admin tools for email diagnostics and an `UpdateLogManager` for curating and AI-generating weekly project updates. Promo expiry reminders are managed with idempotency to prevent duplicate sends.
- **Improvement Log Mirroring:** Agent's `logImprovement()` mirrors entries to a production database for centralized tracking via HMAC-SHA256 signed HTTP.
- **Session Overlays:** Per-session VWAP (with ±1σ bands) and Opening Range (ORH/ORL) overlays are displayed on live charts for spot equities, FX, and commodities, and provided to the AI Analyst.
- **Signal Engine v1 (deterministic Python scorer feeds prompt; AI is veto-only):** Spec is code — the `SIGNAL_ENGINE_V1` constant in `server/prompts/shared.ts`, injected into the v2 signal-gen prompt (`server/prompts/signalGen.ts`). `TradePlanSchema` carries optional engine fields (regime, direction_probability, conviction, kelly_fraction_applied, microstructure, gates_passed, no_signal_reason, etc.) for backward compat, plus `NO_TRADE_REASONS` like `regime_chop` / `cvd_contradict`. Python side (`quant/`): 5-state regime gate with allowed-types matrix (SCORER-AUTHORITATIVE prepass in the AI prompt), dual score (direction_probability + conviction, per-asset-class thresholds, fail-closed, legacy z_threshold removed), vol-adjusted R:R (RANGE capped 1.00), Kelly meta-shrinkage (`min(0.25, …)` with HIGH_VOL 0.5x), and crypto-only microstructure (CVD + OBI live with hard `cvd_contradict` gate; IV-RV deferred). Full phase-by-phase notes in git history.
- **Trade Ideas Hardener (post-LLM, /api/ai/analyze + /api/kronos):** Mechanical risk gates run AFTER the LLM — `server/lib/signalHardening.ts`'s `hardenSignal()`: Gate 0 directional-geometry repair (see Recent Decisions), ATR(1h)-floored stop, CHASE flag (>4% adverse 24h move), CROWDED flag (funding ≥0.01%/8h + OI rising), Wilson 95% CI on backtest WR, quarter-Kelly size off CI lower bound, regime leverage cap, post-haircut conviction veto. Materially-mutated cards trigger an optional prose regen via `server/lib/rationalePrompt.ts`. Wrapped in try/catch — on any hardener error the original LLM output flows through unmodified.
- **Morning-brief no-send fix (Apr 30 2026 miss):** `server/dailyBrief.ts` `_attemptBrief()` inspects structured `BriefSendResult` instead of "did it throw". Stamp matrix: queued/claimed/sent>0/no-subscribers → stamp; pre-send exception or data-integrity sent=0 → leave UNSTAMPED for retry. `_briefInFlight` guard prevents heartbeat racing 6 ET tick; boot catch-up tick fires late if Railway restarted past BRIEF_HOUR_ET.
- **Access Code Redemption (Race-Safe, Per-User Ledger):** `/api/verify-code` is hardened against the live spam-redemption exploit on shared codes (e.g. `CLVR-VIP-GROUP2026`). Each access code carries a `redemption_type`:
  - `single_use_global` — locks to the first redeemer (default for individual VIPs, trial codes, admin Pro codes).
  - `single_use_per_user` — group/shared codes any verified user may redeem exactly once each.
  Enforcement combines (a) email-verified gate, (b) 5-attempt-per-hour per-user audit-backed rate limit, (c) transactional `SELECT … FOR UPDATE` + `INSERT … ON CONFLICT DO NOTHING` against the `code_redemptions` ledger, (d) tier-no-downgrade rule, (e) no-shorten expiry rule. Every attempt writes a `redemption_attempts` row. One-time grandfather backfill seeds prior `users.promo_code` claims into the ledger. Tables + `redemption_type` added via additive raw SQL in `server/initDb.ts`.
  - **Documented exception to the "Drizzle only" preference:** the redemption transaction in `server/routes.ts` uses raw `pg` because Drizzle does not cleanly express row-locked inserts with conflict-aware short-circuiting in a single transaction.
- **Module 3 — PostTradeAnalyzer (Phase A shipped May 2026, shadow mode; details in git history):** Every resolved scanner signal gets a deterministic one-line diagnosis (13-rule tagger in `server/lib/postTradeAnalyzer.ts`, no AI call) via a 60s worker that waits ≥35min post-resolve; single-fire is guaranteed by the resolver's compare-and-set hook in `outcomeResolver.ts`. Surfaced in the JOURNAL tab (`SignalsDiagnosisPanel`, `GET /api/journal`) and a Sunday 22:00 ET weekly model report (`server/lib/weeklyModelReport.ts`). Flags: `PTA_ANALYZER_ENABLED` (default true), `PTA_JOURNAL_DISPLAY_ENABLED` (false), `PTA_WEEKLY_REPORT_ENABLED` (false), `PTA_MODEL_ADJUSTMENTS_ENABLED` (Phase B — auto-adjust loop — deferred). Schema is additive in `initDb.ts`: `post_trade_analysis`, `model_adjustments`, `archetype_scorecard` MV.
- **Module 2 — Setup Taxonomy + Per-Setup Stats (T01–T14 shipped May 2026; supersedes Module 1 + Phase 0; details in git history):** Shared classifier `server/lib/archetypeClassifier.ts` (336-bar 1h lookback, Wilder daily ATR once ≥15 bars, per-call diagnostics); shared funding/OI via `microstructureSnapshot.ts`; all three endpoints classify through `classifyForLive(ctx)` — `/api/quant` keeps its MEAN_REV auto-flip, `/analyze` + `/kronos` only expose a `recommendedFlip` boolean. Stats show Wilson 80% LCB primary with LOW SAMPLE prefix at n≤20. `archetype_stats` MV + hourly refresher (`statsMvRefresher.ts`, manual trigger `POST /api/admin/archetype/refresh-stats`); admin-triggered Binance backfill script; admin "ARCH" tab (`GET /api/admin/archetype/summary`); fixture tests 12/12. Flags: `ARCHETYPE_SUPPRESSION_ENABLED` (false — shadow logs `suppressed_signals`), `USE_BACKFILLED_STATS`, `STATS_SOURCE` ("ts"|"mv", default "ts", MV falls open to TS), `USE_ARCHETYPE_DISPLAY` (false). All DB objects additive via `initDb.ts` (4 tables, 1 plpgsql fn, 1 MV + unique index, 2 `ai_signal_log` columns).
