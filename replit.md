# CLVRQuantAI

## Overview
CLVRQuantAI is a luxury, mobile-first market intelligence dashboard for real-time analysis across crypto, equities, commodities, and forex. It provides AI-driven market insights, a macro calendar, personalized alerts, and a morning brief to support informed trading decisions. The project aims to transition from AI-originated signals to a deterministic quant scorer, with AI serving a veto-only role, enhancing signal reliability and precision.

## System Architecture
The application features an Express (TypeScript) backend and a React (JSX) frontend, served via Vite on a single port. Data is persisted in PostgreSQL using Drizzle ORM. A Python FastAPI quant microservice handles deterministic quantitative scoring. The UI/UX employs a navy and gold theme with Playfair Display and IBM Plex Mono fonts.

**Key Architectural Components & Features:**
- **Quant Microservice:** A Python FastAPI service (`quant/`) generates deterministic quantitative scores, including modules for scoring, risk management (stop-loss, sizing), regime detection, GARCH modeling, and microstructure analysis.
- **Node-Python Bridge:** `server/quantClient.ts` facilitates communication between the Node.js backend and the Python quant microservice.
- **Real-time Data Aggregation:** Aggregates 1-minute OHLCV bars from sources like Hyperliquid, Binance, and Yahoo Finance.
- **Signal Generation & Hardening:** Signals originate from the quant service, are subject to cost/EV gates, and an AI veto. Signal hardening rules (e.g., `MIN_RR_AFTER_FRICTION`) optimize throughput and reduce noise.
- **Statistical Brain:** An empirical edge engine (`server/lib/statisticalBrain.ts`) analyzes historical trade data to compute win rates, expected returns, and resolution times per (token, direction) combo. It derives strict limits for Take Profits, Stop Losses, and Kill Clocks, issuing verdicts: **INVERT** (WR<15% & n≥20, opposite side not also weak — flip direction), SUPPRESS (WR<25% & n≥20), CAUTION, NORMAL, or PREFERRED. This brain context is integrated into the AI's prompts and can veto/flip signals.
- **Edge Policy (Phase 0 — INVERT loser combos):** `applyEdgePolicy(token, direction, rawConvictionPct)` and `recalibrateConviction()` in `server/lib/statisticalBrain.ts` translate brain verdicts into deterministic post-LLM actions: SUPPRESS drops the card; INVERT mirrors stop/targets around entry via `mirrorPrice()` and flips direction; conviction recalibration clamps INVERT/SUPPRESS verdicts at ≤25 and caps any raw≥50 at 40 for NORMAL/CAUTION, while PREFERRED passes through untouched — fixing the inverted calibration found in dev data (60-bucket=14% WR vs 30-bucket=36% WR). Wired into BOTH `/api/ai/analyze` `hardenTradeIdeas` (server/routes.ts ~6885) and `/api/kronos` (server/routes.ts ~7794) BEFORE `hardenSignal()`. Cards expose `edgePolicy: {action, originalDirection, recommendedDirection, brainVerdict, rawConvictionPct, recalibratedConvictionPct, reason}` and an `edge-inverted` hardener flag; INVERT forces `materiallyMutated=true` to trigger rationale regen so prose matches the flipped direction. Live dev-DB calibration confirms 4 INVERT combos (BTC SHORT n=20 0% WR, DOGE SHORT n=21 4.8% WR, APT SHORT n=25 8% WR, WIF LONG n=20 5% WR) and 3 PREFERRED combos that bypass the cap (BNB LONG 84%, BTC LONG 66%, ETH LONG 61%). Falls open on any error.
- **Chart Vision:** `server/lib/chartRenderer.ts` generates SVG candlestick charts with technical overlays (EMAs, S/R, entry zones), converts them to PNG, and sends them as multimodal input to Claude for visual analysis validation.
- **Enhanced AI Analysis (`/api/ai/analyze`):** Integrates the Statistical Brain, Chart Vision, and intraday Execution Levels (VWAP, ORH, ORL) into the AI's context for a comprehensive analysis of user-specified tickers.
- **Daily Brief Integration:** The Statistical Brain context is used to bias trade idea selection in the daily email brief and Telegram posts, favoring empirically winning setups and avoiding suppressed ones.
- **Trade Idea Asset Class Selector:** UI allows filtering trade ideas by asset class (All, Crypto, Equities, Commodities, Forex), dynamically adjusting market types (PERP/SPOT) and filtering signals accordingly.
- **Telegram Autoposter:** A unified helper (`server/lib/buildEnrichedReasoning.ts`) creates consistent, branded captions for live signals and daily brief trade ideas, posted via a dedicated webhook. Includes admin tools for testing posts.
- **Email & Update Management:** Admin tools for email diagnostics and an `UpdateLogManager` for curating and AI-generating weekly project updates. Promo expiry reminders are managed with idempotency to prevent duplicate sends.
- **Improvement Log Mirroring:** Agent's `logImprovement()` mirrors entries to a production database for centralized tracking via HMAC-SHA256 signed HTTP.
- **Session Overlays:** Per-session VWAP (with ±1σ bands) and Opening Range (ORH/ORL) overlays are displayed on live charts for spot equities, FX, and commodities, and provided to the AI Analyst.
- **Signal Engine v1 (deterministic Python scorer feeds prompt; AI is veto-only):** Spec encoded as `SIGNAL_ENGINE_V1` constant in `server/prompts/shared.ts`, injected into v2 signal-gen prompt at `server/prompts/signalGen.ts`. `TradePlanSchema` extended with optional fields (`signal_status`, `regime`, `direction_probability`, `conviction`, `p_loss_meta`, `vol_percentile`, `rr_multiplier`, `kelly_fraction_applied`, `microstructure`, `gates_passed`, `no_signal_reason`) — all optional for backward compat. New `NO_TRADE_REASONS`: `regime_chop`, `regime_mismatch`, `below_thresholds`, `cvd_contradict`, `ivrv_block`. Implementation phases (all DONE except IV-RV):
  - **2.1 Regime Gate (Python):** `quant/regime.py` — 5-state classifier (`TREND_UP/TREND_DOWN/RANGE/HIGH_VOL/CHOP`) using `percentile_rank(ATR(14),90) + ADX(14) + BB_width + EMA alignment`. `regime_allows(regime, side, signal_type)` enforces allowed-types matrix. `quant/scorer.py` classifies `signal_type` (momentum vs mean_reversion) from weighted factor magnitudes. Wired through `/api/quant` shadow IIFE: scorer's `regime/signal_type/no_signal_reason` reach the AI as a `SCORER PREPASS` line; SCORER-AUTHORITATIVE block in §1 tells AI to defer. Asset-class derivation maps `cls` → METAL/FOREX/STOCK; crypto branch uses symbol heuristic so BTC/ETH escape MID_CAP_DEFAULT.
  - **2.2 Dual Score (Python):** `compute_dual_score()` returns `direction_probability = clip(0.50 + 0.30*tanh(|directional_z|/3.0), 0.50, 0.85)` from PURELY directional features (momentum/meanrev/flow/sentiment; carry+volgate excluded) and `conviction = clip(0.40 + 0.25*alignment + 0.15*regime_fit + 0.10*no_conflicts + 0.10*data_freshness, 0.40, 0.95)`. Per-asset-class thresholds in `DUAL_SCORE_THRESHOLDS` (BTC/ETH `0.58/0.60`, MID_CAP `0.62/0.68`, FOREX `0.55/0.55`, METAL `0.57/0.60`, STOCK `0.56/0.58`); fail-closed default. Legacy `z_threshold` gate REMOVED to avoid dual-source `below_thresholds` false rejections. PREPASS line carries 4-decimal values; SCORER-AUTHORITATIVE block instructs AI to emit verbatim.
  - **2.3 Vol-Adjusted R:R (Python):** `compute_vol_adjusted_rr()` returns `(vol_percentile, rr_multiplier)` from 90-bar percentile rank of `ATR(14)/close` ratio (not raw ATR — avoids inflation under price drift). Buckets `0.20/0.60/0.85 → 0.70/1.00/1.30/1.60`, RANGE regime capped at 1.00.
  - **2.4 Kelly meta-shrinkage:** `compute_p_loss_meta_proxy = clip(1 - direction_probability, 0, 1)` (Phase-3 placeholder until trained meta-classifier lands). `kelly_fraction_applied = min(0.25, kelly_base, kelly_base*(1-p_loss_meta)*regime_size_modifier*conviction)` with `HIGH_VOL → 0.5x` modifier, computed server-side in `server/routes.ts` (kelly_base needs per-(token,direction) calibration). Double-cap enforces "never size up because p_loss_meta is low".
  - **2.5 Crypto microstructure (CVD+OBI live; IV-RV deferred):** `compute_microstructure()` crypto-only. **CVD:** `cvd_z` ≥30 samples + 20-bar return correlation → ±0.06 divergence / ±0.04 confirmation deltas; `cvd_contradict` hard gate fires at `base_conviction<0.65`. **OBI:** top-10 `l2Book` levels, ±0.20 thresholds, asymmetric +0.05 / −0.10 deltas (bigger penalty for fighting the book), staleness gated by per-book `STATE.books_ts` stamped in `quant/hl_ws.py`. **IV-RV:** always `null` until Deribit ATM 7-day IV feed lands. All §5 adjustments fold into dir_prob/conviction BEFORE threshold gating; SCORER-AUTHORITATIVE blocks tell AI not to re-apply.

  - **Live smoke verified across BTC/ETH/XAU/EURUSD/NVDA:** `z_threshold` removed from all `gates_failed`, `below_thresholds` single-source, BTC dir_prob matches expected directional-only formula, PREPASS line snapshot-stable, legacy callers without prepass produce no PREPASS line (backward compat). BTC live: `regime=TREND_UP, vol_percentile=0.82, rr_multiplier=1.30, p_loss_meta=0.466, microstructure.obi=0.18`. AAPL: microstructure correctly all-null, vol_percentile/rr_multiplier still emitted.
- **Trade Ideas Hardener (post-LLM, /api/ai/analyze + /api/kronos):** Mechanical risk gates run AFTER the LLM responds — `server/lib/signalHardening.ts`'s `hardenSignal()` (separate API from the scanner-side `applySignalHardening` above): ATR(1h)-floored stop, liquidity-cluster shift (when wired), CHASE flag (>4% adverse 24h move), CROWDED flag (funding ≥0.01%/8h + OI rising), Wilson 95% CI on backtest WR, quarter-Kelly size off CI lower bound, regime leverage cap (RISK_OFF→3x, MACRO_EVENT→2x), post-haircut conviction veto. Wired in `/api/ai/analyze` (only when response parses as `{trades:[...]}` — Morning Brief and Ask AI pass through) and `/api/kronos` (only when `trade_plan.direction` is LONG/SHORT). Materially-mutated cards trigger an optional prose regen via `server/lib/rationalePrompt.ts` (`RATIONALE_REGEN_SYSTEM_PROMPT` + `buildRationaleUserMsg`). Discipline rules ("no superlatives", regime consistency, sample-size honesty, funding calibration, OI scope, chase disclosure, number matching) added to system prompts in `client/src/components/ai/TopTradeIdeas.jsx`, `client/src/components/ai/AIChat.jsx`, `client/src/App.jsx` (Ad-hoc Analyst), and the inline chart-AI prompt in `server/routes.ts` so Claude gets prose right on the first pass and avoids regen round-trips. Both wire-ins wrapped in try/catch — on any hardener error the original LLM output flows through unmodified.
- **Morning-brief no-send fix (Apr 30 2026 miss):** `server/dailyBrief.ts` `_attemptBrief()` inspects structured `BriefSendResult` instead of "did it throw". Stamp matrix: queued/claimed/sent>0/no-subscribers → stamp; pre-send exception or data-integrity sent=0 → leave UNSTAMPED for retry. `_briefInFlight` guard prevents heartbeat racing 6 ET tick; boot catch-up tick fires late if Railway restarted past BRIEF_HOUR_ET.
- **Access Code Redemption (Race-Safe, Per-User Ledger):** `/api/verify-code` is hardened against the live spam-redemption exploit on shared codes (e.g. `CLVR-VIP-GROUP2026`). Each access code now carries a `redemption_type`:
  - `single_use_global` — single-use codes that lock to the first redeemer (default for individual VIPs, trial codes, admin Pro codes).
  - `single_use_per_user` — group/shared codes (CLVR-VIP-GROUP2026) that any verified user may redeem **exactly once each**.
  Enforcement combines (a) an email-verified gate, (b) a 5-attempt-per-hour per-user audit-backed rate limit, (c) a transactional `SELECT … FOR UPDATE` on the access-code row plus `INSERT … ON CONFLICT DO NOTHING` against the `code_redemptions` ledger (UNIQUE(code, user_id)), (d) a tier-no-downgrade rule, and (e) a no-shorten expiry rule that never reduces a user's existing access window — `promo_code` / `promo_expires_at` are only refreshed when the new code STRICTLY EXTENDS the user's current access (a NULL/permanent expiry always wins over any finite date). Every attempt — success, duplicate, expired, exhausted, rate-limited, error — writes a row to `redemption_attempts` for forensics. A one-time grandfather backfill seeds prior `users.promo_code` claims into the ledger so legitimate holders are never charged twice. Both new tables and the `redemption_type` column were added via additive raw SQL `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` in `server/initDb.ts` (no Drizzle schema changes, no `db:push` run).
  - **Documented exception to the "Drizzle only" preference:** the redemption transaction in `server/routes.ts` uses raw `pg` (`pool.connect()` → `BEGIN` / `SELECT FOR UPDATE` / `INSERT ON CONFLICT` / `COMMIT`) because Drizzle's high-level API does not cleanly express row-locked inserts with conflict-aware short-circuiting in a single transaction. The handler always releases the client in `finally` and writes a `claim_error` audit row on any catch.
