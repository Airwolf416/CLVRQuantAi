## 1 — Basket: make the AI as smart as Trade Ideas / Ask AI

**File:** `client/src/components/MyBasket.jsx` (the basket analyze call). Basket stays Elite-only.

**Problem:** Basket calls `/api/ai/analyze` with only `{ system, userMessage }`. It gets none of the context that makes the other tools smart — no Statistical Edge Brain, no execution levels (VWAP/opening range), no unusual-activity flags, no macro pre-flight, and none of the writing-discipline guardrails. So it reasons blind.

**Fix:** mirror the Ask AI request. Before the fetch, pull macro pre-flight; pass the selected symbols as `tickers` and set `attachBrainSummary: true` so the server injects per-asset brain + exec + unusual-activity context; and append the same discipline rules to the system prompt.

**Step A — fetch macro pre-flight + build the symbol list** just above the existing `const r = await fetch("/api/ai/analyze", ...)`:

```jsx
      // Macro pre-flight + smart context (mirrors Ask AI / Trade Ideas).
      let basketPreflight = null;
      try {
        const pf = await fetch("/api/macro/preflight", { credentials: "include" });
        if (pf.ok) basketPreflight = await pf.json();
      } catch {}
      const macroLine = basketPreflight?.clear === false
        ? `MACRO PRE-FLIGHT: CAUTION — ${basketPreflight?.nextEvent || "event window"} active. Dampen conviction and avoid fresh entries near the event.`
        : `MACRO PRE-FLIGHT: CLEAR — no blocking macro event in the basket's trade window.`;
      // Server validates tickers as 1–10 char A–Z0–9, so international symbols
      // like 2222.SR / 9984.T are dropped automatically (they just won't get a
      // brain block — that's fine).
      const basketTickers = selList.map(a => String(a.sym).toUpperCase());
```

**Step B — add discipline + macro to the system prompt.** FIND the end of the basket `system` string (the closing backtick after “Be specific, numerical, and direct.`”) and extend it:

```jsx
Be specific, numerical, and direct.

${macroLine}

WRITING DISCIPLINE (mandatory):
- No superlatives ("best/highest/largest/most") without ranked data in the snapshot — use "elevated/notable".
- Funding |x| < 0.01%/8h is "near-flat", not "momentum".
- A LONG after >+4% (or SHORT after <-4%) in 24h is a CHASE — say so, don't call it a fresh breakout.
- If a Statistical Brain block shows < 30 resolved trades for a (token, direction), call it "small sample (n=X)".
- Account for correlation across the basket; flag geographic/sector concentration.
- Any price/%/RR/leverage in prose must match the structured numbers exactly.
- This is information/education, not financial advice.`;
```

**Step C — enrich the request body.** FIND:

```jsx
        body: JSON.stringify({ system, userMessage }),
```

REPLACE:

```jsx
        body: JSON.stringify({
          system,
          userMessage,
          tickers: basketTickers,        // → per-asset Statistical Brain + VWAP/OR + unusual-activity context
          attachBrainSummary: true,      // → global top/suppressed combos
        }),
```

**Acceptance:** the basket analysis now references empirical edge stats, session levels, macro state, and obeys the discipline rules; international tickers degrade gracefully; Basket remains Elite-only; temperature is already pinned by the earlier `/api/ai/analyze` change.

## 2 — Markets tab: auto-scroll to top on open

**File:** `client/src/App.jsx` (the shell that owns `tab` / `setTab` and the bottom nav).

**Problem:** opening the Markets tab can land mid/bottom of the list instead of the top.

**Fix:** reset scroll to top whenever the active tab changes (covers Markets and every tab). Add this effect near the other `useEffect`s in the App component (it owns `tab`):

```jsx
  // Reset scroll to the top whenever the user switches tabs (fixes Markets
  // opening part-scrolled). Targets window + the main scroll container.
  useEffect(() => {
    try {
      window.scrollTo({ top: 0, left: 0, behavior: "auto" });
      const main = document.querySelector("[data-app-scroll]") || document.scrollingElement || document.documentElement;
      if (main) main.scrollTop = 0;
    } catch {}
  }, [tab]);
```

If the main scrollable content container doesn’t already have it, add `data-app-scroll` to that container’s wrapper div so the selector hits it.

**Acceptance:** switching to Markets (or any tab) always starts at the top; no change to tab logic or gating.

## 3 — “Enable alerts” works for everyone (honest capability handling)

**File:** `client/src/App.jsx` — the `requestPush` handler (the LIVE ALERTS “ENABLE” button).

**Problem:** on devices where web push isn’t available (iOS Safari in a normal tab, in-app webviews), the handler shows “In-app alerts enabled” but never actually wires anything, and `Notification.requestPermission()` silently no-ops. So users think alerts are on when they aren’t, and in-app alerts may not turn on either.

**Fix:** make the flow capability-aware and always enable IN-APP alerts regardless of OS-push support, with an honest message and an iOS “Add to Home Screen” hint.

Replace the `if(typeof Notification==="undefined"){...}` branch and the final fallback with capability detection:

```jsx
    // ── Capability-aware enable ─────────────────────────────────────────────
    const isStandalone = (typeof window !== "undefined") &&
      (window.matchMedia?.("(display-mode: standalone)")?.matches || window.navigator?.standalone === true);
    const pushCapable = (typeof Notification !== "undefined") &&
      (typeof navigator !== "undefined") && !!navigator.serviceWorker && ("PushManager" in window);

    // Always turn ON in-app alerts (toasts + alert history) — works everywhere.
    setPushDisabled(false);
    try { localStorage.removeItem("clvr_push_disabled"); } catch (e) {}
    setInAppAlertsEnabled?.(true);            // if such a state exists; otherwise persist a flag:
    try { localStorage.setItem("clvr_inapp_alerts","1"); } catch (e) {}

    if (!pushCapable) {
      setToast(isStandalone
        ? "In-app alerts on. Lock-screen push isn't available on this device."
        : "In-app alerts on. For lock-screen alerts, add CLVRQuant to your Home Screen, then enable again.");
      return;
    }
    // pushCapable → existing requestPermission + pushManager.subscribe flow runs as before.
```

Keep the existing granted/disabled re-subscribe branches. The key changes: (1) in-app alerts always flip on; (2) the success/【toast】 text tells the truth about lock-screen push; (3) iOS Safari users get the Home-Screen instruction instead of a false “enabled.”

Also confirm the in-app alert stream (ALERT HISTORY + floating banner) renders off the in-app flag, NOT off `Notification.permission` — so a user with push denied still sees in-app alerts.

**Acceptance:** every signed-in user can enable in-app alerts; the toast never claims push is on when it isn’t; iOS tab users get the Add-to-Home-Screen hint; ALERT HISTORY populates regardless of OS push permission.
