2. BACKEND ENDPOINTS (Express)
═══════════════════════════════════════════════════

Create new route file `routes/booking.js`:

GET /api/booking/availability
- Returns array of available 30-min slots for next 60 days
- Rules:
  • Must be ≥ 7 days from today (1 week advance booking minimum)
  • Mon–Fri: 6:00pm–10:00pm America/Toronto (slots: 18:00, 18:30, 19:00, 19:30, 20:00, 20:30, 21:00, 21:30)
  • Sat–Sun: 3:00pm–10:00pm America/Toronto (slots: 15:00, 15:30 ... 21:30)
  • Exclude any date that has a confirmed booking (max 1 call/day)
  • Exclude past slots
- Return: [{ date: "2026-05-15", slots: ["18:00", "18:30", ...] }]

POST /api/booking/create-checkout
- Body: { user_id, slot_date, slot_time, timezone }
- Logic:
  1. Re-validate slot availability (DB lock to prevent race)
  2. Look up user's current tier
  3. Determine price:
     - Elite + elite_session_used_this_month=false → $0
     - Elite + already used → $49
     - Pro → $99
     - Free → $149
  4. If $0: create booking with status=confirmed, payment_status=comped, mark elite_session_used_this_month=true, call createGoogleMeetEvent(), trigger all confirmation emails
  5. If >$0: create Stripe Checkout Session with metadata { user_id, slot_date, slot_time, timezone }, return checkout URL

POST /api/booking/stripe-webhook
- Listen for `checkout.session.completed`
- Pull metadata, store stripe_payment_intent_id, create booking row, call createGoogleMeetEvent(), send all confirmation emails

GET /api/booking/my-bookings
- Returns logged-in user's upcoming + past bookings

POST /api/booking/cancel/:id
- CANCELLATION POLICY LOGIC:
  1. Get booking. Confirm it belongs to logged-in user. Confirm status='confirmed'.
  2. Calculate hours_until_booking = (booking_datetime_utc - now_utc) / 3600
  3. If hours_until_booking >= 24:
     • Set refund_eligible = true
     • If payment_status='paid': call Stripe refunds.create({ payment_intent: stripe_payment_intent_id })
     • If payment_status='comped' (Elite free): restore elite_session_used_this_month=false
     • Update status='cancelled_by_user', cancelled_at=now
     • Cancel Google Calendar event (calendar.events.delete with sendUpdates='all')
     • Send cancellation confirmation emails to user + support@clvrquantai.com (refund issued)
     • Free up the date for re-booking
  4. If hours_until_booking < 24:
     • Set refund_eligible = false
     • Do NOT issue refund
     • Update status='cancelled_by_user', cancelled_at=now
     • Cancel Google Calendar event
     • Send cancellation confirmation emails to user + support@clvrquantai.com (NO refund — under 24h policy)
     • Free up the date for re-booking
  5. Return: { success: true, refunded: boolean, message: string }

6. EDGE CASES & RULES
═══════════════════════════════════════════════════

- Times stored UTC, displayed in user's TZ
- "1 week advance" = 7×24h from now (use date-fns or moment-timezone)
- Max 1 call/day: WHERE booking_date=X AND status='confirmed' — if count≥1, block date
- Stripe abandonment: slot only reserved on webhook success (not on checkout creation)
- Race condition: use SELECT...FOR UPDATE on booking creation
- Refund window: calculated in UTC, rounded down (23h 59m = no refund)
- If Elite user cancels free session ≥24h: restore their monthly free credit
- Google Calendar event cancellation must use sendUpdates='all' so user gets native Google cancellation notice too
