CLVRQuantAI — SESSION SECURITY + UI POLISH (zero disruption to active users)

DISCOVERY FIRST (do not assume line numbers):
1. Locate the session/auth setup in server/routes.ts or server/index.ts
   (express-session or equivalent, cookie config, login/signup handlers).
2. Locate the client-side auth state + the 12-second chat polling loop in
   client/src/App.jsx.
3. Locate the main card components (SignalCard, trade idea cards), tab
   navigation, and any loading states.
Report file + function names found before changing anything.

━━━ PART A — 8-HOUR INACTIVITY LOGOUT ━━━
1. Server: add lastActivityAt to the session (or a session-store field).
   Middleware on all authenticated routes:
   - if now - lastActivityAt > 8 hours → destroy session, respond 401 with
     JSON { code: "SESSION_IDLE_EXPIRED" }
   - CRITICAL: do NOT refresh lastActivityAt on background/polling routes.
     Identify the chat polling endpoint and any other auto-refresh endpoints
     (market data refresh, signal feed refresh) and add them to a
     POLLING_ROUTES exclusion list. Only genuine user-triggered routes and
     the heartbeat below refresh activity.
   - Add absolute session lifetime cap: 30 days from login regardless of
     activity (code "SESSION_MAX_AGE").

2. Client: activity tracker in App.jsx:
   - Listen for pointerdown, keydown, scroll (passive), visibilitychange-to-
     visible. Throttle: send POST /api/session/heartbeat at most once per
     5 minutes while genuinely active.
   - Idle warning: after 7h45m without tracked activity, show a small
     non-blocking banner: "You'll be signed out in 15 minutes due to
     inactivity — tap anywhere to stay signed in." Any interaction dismisses
     it and sends a heartbeat.
   - On any 401 with SESSION_IDLE_EXPIRED / SESSION_MAX_AGE: clear auth
     state, redirect to login, show a friendly "You were signed out for
     security. Sign back in to continue." message. Never a silent failure or
     raw error. Preserve the tab the user was on and return there post-login.

━━━ PART B — INVISIBLE SECURITY HARDENING (already-flagged audit items) ━━━
1. Rate limiting (express-rate-limit) on /api/login, /api/signup, password
   reset: 10 attempts / 15 min per IP, generic error message on limit.
2. Session fixation: regenerate the session ID on successful login.
3. Remove any temp/reset password value from API JSON responses — deliver
   only via the existing Resend email path.
4. Cookie audit: confirm httpOnly, secure, sameSite=lax on the session
   cookie; set them explicitly if inherited defaults are ambiguous.
5. Do NOT add CAPTCHA, forced re-login for currently active users, or any
   flow change a legitimate user would notice.

━━━ PART C — ANIMATION POLISH ━━━
Constraints (non-negotiable):
- Animate ONLY transform and opacity (GPU-composited). Never width/height/
  top/left. No layout thrash.
- Wrap everything in a prefers-reduced-motion media check that disables all
  decorative motion.
- Durations 150–300ms, ease-out for entrances, ease-in for exits. Subtle >
  flashy — this is a financial product, not a game.
- Mobile-first: must feel smooth on iPad/phone Safari.

Apply:
1. Card entrances: signal/trade-idea cards fade-up (opacity 0→1,
   translateY 8px→0) with a 40ms stagger per card, on first render and on
   feed refresh. New cards arriving into an existing list animate in; existing
   cards do not re-animate.
2. Tab transitions: 150ms opacity crossfade on tab content switch.
3. Press feedback: buttons and tappable cards scale to 0.98 on active state,
   spring back on release.
4. Loading: replace any spinner-only states on card lists with skeleton
   placeholders using a subtle shimmer (background-position animation on a
   gradient — composited, cheap).
5. Conviction/strength meters: animate fill from 0 to value over 400ms
   ease-out on first paint only.
6. Idle-warning banner (Part A): slide-down entrance, slide-up exit.
7. Numbers that update in place (prices): brief 200ms color pulse (green up /
   red down) via opacity on an overlay — no layout shift, and throttle so a
   ticking price doesn't strobe.

━━━ DO NOT TOUCH ━━━
- Signal engine, risk controls, compliance copy, subscription gating.
- The chat polling interval itself (WebSocket migration is separately scoped).

━━━ ACCEPTANCE CRITERIA ━━━
1. A session with only chat-polling traffic for 8h+ gets 401
   SESSION_IDLE_EXPIRED on the next user-triggered request.
2. Real interaction (tap/scroll) keeps the session alive indefinitely up to
   the 30-day absolute cap.
3. Idle banner appears at 7h45m idle; any tap dismisses and extends.
4. Expired users land on login with the friendly message and return to their
   prior tab after signing in.
5. 11th login attempt in 15 min from one IP is rate-limited.
6. Session ID differs before vs after login (fixation test).
7. No temp password string appears in any API response body (grep test).
8. With prefers-reduced-motion enabled, no decorative animation runs.
9. No animation triggers layout (verify with DevTools performance pass —
   transform/opacity only).
10. TypeScript compiles clean; existing flows (upgrade, AI features) unaffected.
